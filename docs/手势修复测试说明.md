# 手部跟踪兼容测试版 1.0.2

文件：`XREAL-HandFix-v1.0.2.apk`。包名与综合 Demo 相同，versionCode 12，可覆盖 1.0.0 和 1.0.1 诊断版。**Server 1.0 不需要更新**。原正式 APK 和诊断 APK 保留，便于对照。

## 已确认的问题

在小米 15 / Android 17 / Air 2 Ultra 的实机日志中，手部模块选中了 `graph_flora_cpu.txt`，随后算法图校验失败：

- `HandLiftCalculator` 缺少 `HEADPOSE` 输入；
- `HandFilterCalculator` 缺少 `GR_KPT2D_INPUT` 输入。

已从诊断 Demo 读取到图的明文，确认 CPU 图确实没有这两条连接，而现有节点已经输出所需的 `head_pose_out` 与 `kpt2d`。相邻 DSP 图也有相应连接。此前界面的开启成功仅代表输入源切换返回 True，算法初始化实际上失败，因此没有关节数据。

这不能证明所有 Android 17 设备都存在同一问题。`hand_num` 警告是后续表现，未据此修改数量边界。

## 本版处理

新 Demo 增加 `libXrealHandCompat.so` 和启动代码。兼容层只在本 Demo 进程内工作：

1. 确认被加载的是已审计的 `libnr_hand_tracking.so`（GNU Build ID 和原输入 APK 对应）。
2. 调整该模块自身的 `memcpy` / `memmove` 导入数据槽，其他模块不参与。
3. 当读取的内容**完整匹配**那份 3785 字节 CPU 图时，提供补齐两条输入的等长配置。不同内容、截断内容、其他型号图均原样复制。
4. 保留模型名称与模型文件，保留官方运行库文件。补丁不写入系统、固件或其他应用，退出 Demo 即结束。

为保持同一长度，补丁去掉原图中的注释和多余空白，在末尾补空格。恢复的连接为：

```text
HandLiftCalculator.HEADPOSE            <- head_pose_out
HandFilterCalculator.GR_KPT2D_INPUT    <- kpt2d
```

本版还接收 SDK 原生错误回调。发生手部初始化错误后会显示 `Hand algorithm failed`，不再仅显示输入源被接受。

这是**待实机验证的兼容测试版**。手机断开后继续完成了离线构建；没有宣称已经看到骨架或完成手部识别。此兼容处理目前作用于新 Demo；其他 XR 客户端不会因为 Server 保持运行而自动获得此补丁，需集成同一兼容层。

## 手动测试

1. 手动传输并覆盖安装 `XREAL-HandFix-v1.0.2.apk`，无需卸载或清除应用数据。
2. 打开原 Server，启动完整服务，再启动“手部骨架 / 手势交互”。
3. 查看手机状态中的 `Compat`。预期出现 `installed / imports=... / graph copies repaired=...`；修正命中后 repaired 应大于 0。
4. 若首次初始化错误且 repaired 仍为 0，等 1 秒，关闭再开启手部跟踪一次。这可以区分首次加载时序与配置修正未命中。
5. 在明亮环境把手放在眼镜前方，观察左右手 `26/26 joints` 和骨架，再验证捏合抓取。

结果解释：

| 状态 | 含义 |
|---|---|
| waiting for module | 尚未观察到原生手部模块加载 |
| installed，repaired=0 | 导入兼容层已安装，但尚未命中目标图的复制；不代表算法已修好 |
| repaired>0，仍有 native error | 图已替换，但后续还有原生失败，需要查看报告 |
| unsupported binary | 运行库与已审计版本不同，拒绝修改 |
| data-slot permission failure | 系统未允许调整本模块的导入数据槽 |
| self-test failed / load failure | 兼容库自身未通过启动检查或加载失败 |
| 左右手关节有效并显示骨架 | 实际识别输出已到达 Unity，可继续测试交互 |

如果仍没有手，先保存并复制 Demo 的 JSON 报告；不必现在连接调试手机。报告新增 `handCompatibility`、`handNativeError` 和 `handInputSource`。后续可先根据报告继续分析，再决定是否需要实机日志。
