# XREAL Server 1.0 与空间功能调试 Demo

适用本次工程：小米 15 / Android 17 / XREAL Air 2 Ultra。此前 3DoF 调试功能已由用户反馈正常；本版新增空间能力的构建检查已完成，实机验收尚待进行。

## 安装和启动

1. 手动把 `XrealServer-v1.0.0.apk` 和 `XREAL-FeatureDemo.apk` 传到手机并安装。Server 与上一版包名、开发证书一致，可以覆盖安装；综合 Demo 是独立应用。保留旧的 3DoF 对照 Demo。
2. 退出官方 Control Glasses 和其他 XR 客户端，连接 Air 2 Ultra。
3. 打开 **XREAL Server → 启动完整服务**，允许相机、USB 及通知权限。等待状态为 `READY`。
4. 在 **调试 Demo** 页选择需要测试的功能。Server 会请求立体模式并等待真实外屏达到 **3840×1080**，然后启动客户端。
5. 手机显示操作面板，眼镜显示场景和状态文字。建议先测追踪，再测锚点、手势、环境；每次退出 Demo 后再停止 Server。

若界面仍显示旧应用标题，请检查安装文件名及版本。不要同时运行两套 Server 或多个 XR 客户端。新包不会修改眼镜固件。

## 已接入的能力

| 模块 | 实现与可观察结果 |
|---|---|
| 服务与连接 | 完整模式 `startSdk(1)`；Binder/原生客户端连接；USB 授权、拔出释放、串行工作线程、初始化超时、失败重试、客户端计数。 |
| 设备与显示 | 固件与设备信息、支持的显示模式、亮度、2D/3D、显示开关、独立外屏网格测试；沿用已定位的显示名称兼容修复。 |
| 6DoF / 3DoF | 真实 XR 位置和旋转、有效标志、AR 会话状态与失追原因、运行时模式切换；静止参照物、旋转方块、FPS/帧编号。 |
| 空间锚点 | 创建、选取、质量查询、保存地图、列举地图、加载、重定位状态、重映射、删除地图、清除活动锚点。使用 XREAL Anchor Subsystem。 |
| 手部跟踪 | XR Hands 左右手各 26 个关节及骨架、逐关节有效性；有滞回的捏合识别、抓取/释放方块、可选捏合创建锚点。张掌/握拳为关节几何分类。 |
| 平面与网格 | ARFoundation 平面轮廓和空间网格，独立开关与实时数量。默认关闭，按需测试。 |
| 图像跟踪 | 一个已编译的参考图像库，识别后在目标上显示紫色标记；打印附带 PNG，**整张图片宽 20 cm、高 20 cm**，勿拉伸或裁切。 |
| 相机 | 原生 RGB 能力查询与 CPU 图像帧计数。Air 2 Ultra 的灰度定位相机与 RGB 摄像头是不同能力；无 RGB 时明确报告不支持。 |
| 诊断 | Server 可通过系统文件选择器导出 JSON；Demo 可保存并复制 JSON，包含追踪、关节、锚点、模块计数、能力查询和错误日志。 |

Server 保留官方 APK 的 15 个原生库和协议实现。空间模块由 Unity 客户端通过官方 SDK 按需调用；服务端没有另一套独立的 Java SLAM/手势算法。Server 的 `READY` 表示运行库就绪，各模块的 running、tracking 和检测结果在 Demo 中分别显示。

这是基于已发布 XREAL 3.1 二进制运行库的兼容服务及可编辑 Demo 工程，并非闭源算法的源码重建。账号、商店和 OTA 更新不属于本版空间调试功能。不能据构建成功认定所有 Android 16/17 设备和所有原生模块均已通过兼容测试。

## 实机验收顺序

### 1. 6DoF

在明亮、有纹理的环境启动“6DoF / 世界锁定”。等待 `SessionTracking`、`Position tracking: True`、`Rotation: True`。左右/前后移动头部，确认静止标记产生平移视差并留在原位置；观察旋转方块和帧编号持续更新至少 2 分钟。只有转头悬停不能证明 6DoF 正常。

位置追踪无效时，查看 `reason`（光照、特征、初始化或重定位等）及报告中的 XR flags。先改善场景并等待初始化。保留 3DoF 对照测试以区分基础显示和视觉定位问题。

### 2. 锚点持久化

1. 创建一个视线前方 1 米的锚点。锚点只有进入 `Tracking` 才显示黄色方块。
2. 缓慢从不同角度观察周围环境，查询质量；达到 `SUFFICIENT` 或 `GOOD` 后保存。
3. 记录保存 GUID，退出 Demo，重新启动并进入同一位置。
4. 刷新/选择保存地图，点击加载，观察熟悉的周围纹理。加载返回 `accepted=True` 只表示请求被接受，锚点达到 `Tracking` 才表示已重定位。
5. 确认黄色方块回到原物理位置，再测试删除地图。

地图目录：`/storage/emulated/0/Android/data/dev.xreal.server.features/files/SpatialMaps`。覆盖安装保留；清除应用数据或卸载会删除。地图属于此客户端，不自动跨应用、跨手机共享。保存/删除操作超过 30 秒会提示仍在等待，并阻止并发地图操作；没有假报完成或强行中断原生任务。

### 3. 手势

开启手部跟踪，把双手放在眼镜视野内，检查各自的关节计数与骨架。捏合时拇指尖和食指尖距离小于 25 mm 进入，超过 35 mm 释放，以减少抖动。靠近交互方块捏合并移动，松开放下。丢失手部跟踪也会释放抓取。

“捏合创建锚点”需要有效 6DoF；开启后捏合在指尖中点创建锚点，有 1 秒间隔，Demo 最多 12 个活动锚点。张掌/握拳标签为几何启发式分类，未声称是官方原生手势分类器输出。

### 4. 环境模块

依次单独打开平面、网格、图像，观察新增数量与眼镜标记。图像使用 `XREAL-ImageTarget.png`，按 20 cm 正方形尺寸打印。RGB 若显示不支持，是硬件/运行库能力报告；定位和手部跟踪使用的灰度相机仍需单独验收。

## 报告与问题定位

手机 Demo 的 **报告 → 保存并复制诊断报告** 会复制完整 JSON，并写入：

`/storage/emulated/0/Android/data/dev.xreal.server.features/files/xreal-feature-report.json`

Server 的 **日志 → 导出诊断 JSON** 可自行选择存放位置。出现错误时请提供这两份报告和眼镜中实际现象。FPS 和帧编号停住通常指向客户端渲染/进程问题；持续更新但位置无效则应查看视觉追踪状态，不能混为同一问题。

如需后续手机日志，届时再安排无线调试；本次仅构建交付，没有自动安装或传输。
